# Booki 0.97.0

Booki now understands your AI agents better: Claude's real plan usage and exact states for Claude Code, Codex, Gemini CLI and Cursor, plus flicker-free glass and Windows 11 controls.

## AI agents

- **Claude's real plan usage (optional).** Claude Code hands its status-line command the plan's 5-hour and 7-day percentages. Turn on **Real Claude plan usage** in the AI usage widget and Booki registers itself as that command, keeps only those percentages and reset times, and still runs your own status line so it keeps showing. Turning it off restores your status line.
- **Exact agent states (optional).** Claude Code, Codex, Gemini CLI and Cursor can run a command on prompt, tool use, permission requests and stop. With **Exact … states** on, Booki adds its own hook so the notch knows at once whether an agent is working, waiting for your permission or done, instead of guessing from log silence. Codex asks you to trust the hook once with `/hooks`.
- **Privacy is unchanged.** Booki never reads sign-ins, tokens or credential files and makes no network request for this. Only the percentages, reset times and the event kind per session are written, under `%LOCALAPPDATA%\Booki\agents`; prompts, paths and transcripts are never kept. Each agent's config file is backed up once (`*.booki-backup`) before the first change, and only Booki's own entries are added or removed.
- **Notch card.** A thin bar shows focus time left, battery or charging level and how far the song is (when the player reports it). A working agent shows its logo and how long the turn has run. Several live states take turns every six seconds; one waiting for you stays put.
- The AI widget shows the provider's logo larger and in its colour, and the reading slides in on each turn.

## Glass and controls

- **No see-through flash.** Windows' blur cannot fade with the page, so menus, groups and the notch card on glass showed the desktop for a moment. They now slide in without a fade and wear the theme's solid fill until the blur is behind them; the notch card waits for the blur to leave before it shrinks.
- **Notch to dock.** The notch leaves once the dock has drawn its first frame, so the two are not on screen together.
- **Windows 11 controls.** The toggle switch stretches when pressed and can be dragged; sliders show their value while dragging; errors and notices in Settings use InfoBar; first-run tips use the TeachingTip layout. The dock tooltip is a solid chip that fades.

## Everyday

- **Clipboard like Win+V.** Pinned items first, then recent ones as cards with a three-line preview, when they were copied, and a lock for session-only items.
- **Folders scroll like Explorer** and load more as you reach the end, with the same search and sort fields as groups.
- **Home** shows the dock preview at real size, scrolling sideways when it is long.
- **Logitech keyboards** charging by cable while connected through Bolt show as charging. A percentage that contradicts the keyboard's own level flags is not shown, and the raw reading is logged for diagnosis.

## Under the hood

- The notch follows app and browser-tab switches from Windows events instead of a three-second poll. Agent detection waits for folder-change notices while every agent is idle.
- Dependencies with security fixes (rustls-webpki, webpki roots, tokio, zod, updater) were updated.
- Settings logs any stall longer than 200 ms to help find scroll hitches.

## Not verified on a Windows PC

Automated tests run the interface in a browser with a simulated Windows bridge, and the agent bridge was exercised on Linux. A real PC still needs to confirm: Claude Code, Codex, Gemini CLI and Cursor running Booki as status line and hooks (paths with spaces, Git Bash), the status line output passing through, native glass timing, the notch-to-dock handoff, Logitech readings and the folder-change watcher.
